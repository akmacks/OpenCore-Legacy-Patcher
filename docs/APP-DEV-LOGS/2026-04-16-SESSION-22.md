## 1. Stage 1 Verification (Post-Reboot)

**Action:** Rebooted Macmini5,3 after applying ACPI rename patches (`EHC1` $\rightarrow$ `EH01`, `EHC2` $\rightarrow$ `EH02`).

### Diagnostic Results:
- **ACPI Renames:** ✅ **SUCCESS**. `ioreg` confirms the controllers are now identified as `EH01@1d0007` and `EH02@1a0007`.
- **Driver Attachment:** ✅ **SUCCESS**. `AppleUSBEHCIPCI` is loaded and matched to the renamed controllers.
- **Port Enumeration:** ✅ **SIGNIFICANT IMPROVEMENT**. 
  - **Before:** 0 `AppleUSBEHCIPort` instances. Controllers were comatose.
  - **After:** **6 `AppleUSBEHCIPort` instances** created.
- **USB Stack:** ✅ `AppleUSBHub` is now loaded and active.

### Analysis: Why this worked
The rename broke the match with Apple's built-in, incorrect port map in `AppleUSBHostPlatformProperties.kext`. By renaming the controllers to non-standard names (`EH01`/`EH02`), we forced the driver to fall back to the generic ACPI enumeration process. This restored the ability of the OS to create port objects, effectively "waking up" the controllers from their D3 suspend state.

## 2. Analysis for Stage 2: Port Mapping & UHCI Enablement

While Stage 1 restored the *existence* of ports, the *mapping* is still incomplete. The system currently sees "ports," but it doesn't know their physical properties (e.g., which are external USB-A, which is the internal Bluetooth hub).

### The Gap: Missing `_UPC` and `_PLD`
macOS Tahoe's `IOUSBHostFamily 1.2` requires precise ACPI descriptors to correctly categorize ports. Without specific `_UPC` (User Connectable Port Capabilities) and `_PLD` (Physical Location Description) data, the OS may:
1. Misidentify internal ports as external (or vice versa).
2. Fail to optimize power delivery.
3. Struggle with companion relationship stability.

### The UHCI Situation
There are 7 UHCI controllers in the ACPI. 5 of them (`UHC2-4`, `UHC6-7`) are currently at `_STA=9` (present but disabled).
- **Current State**: We are using EHCI "Transaction Translator" (TT) mode, which handles USB 1.1 devices through the EHCI controller.
- **Proposed Improvement**: Enabling the UHCI controllers via `_STA=0xF` overrides can provide a more native USB 1.1 path, which is often more stable for legacy HID devices (keyboards/mice).

## 3. Proposed Stage 2 Implementation Plan

**Objective**: Create a dedicated SSDT (`SSDT-USB-MAP.aml`) to define the exact physical topology of the Macmini5,3.

### Implementation Details:
1. **UHCI Enablement**: Override `_STA` to `0xF` for the 5 disabled UHCI controllers.
2. **EHCI Port Mapping**:
   - **EH01 (Rear Panel)**: Define 4 ports as `Standard-A` (external).
   - **EH02 (Internal)**: Define the internal hub port (Bluetooth, IR receiver) as `Internal/Proprietary`.
3. **Companion Links**: Explicitly define the companion relationship between the EHCI and UHCI controllers to ensure the most stable hand-off for USB 1.1 devices.

### Verification Steps:
1. Apply SSDT $\rightarrow$ Reboot.
2. Verify `AppleUSBUHCIPCI` instances increase from 0 to 7.
3. Verify `ioreg` shows correct `usb-port-type` for the 4 external ports.
4. Test physical connectivity of all rear ports.
