## Root Cause Identified: UHCI Class Code Mismatch

**Problem:** `AppleUSBUHCIPCI` driver loads but creates **0 instances** despite UHCI controllers (UHC1@1D, UHC5@1A) being present with `_STA = 0xFFFFFFFFFFFFFFFF`.

**Root Cause:** Driver personality expects `IOPCIClassMatch = 0x0C030000`, but hardware presents `class-code = <00030C00>` (0C0300). On Darwin 25.x (Tahoe), this mismatch prevents driver binding.

| Field | Driver Expects | Hardware Presents |
|-------|---------------|-------------------|
| class-code | `0x0C030000` | `0x00030C00` |
| IONameMatch | — | `pci8086,1c27` |
| Result | No match | IOPCIDevice only |

---

## Fix Applied: DeviceProperties Injection

**Method:** OpenCore `DeviceProperties` → `Add` entries to spoof class-code for UHCI controllers.

**Changes to `/Volumes/EFI/EFI/OC/config.plist`:**

### 1. UHC1 @ PCI0 (UHC1@1D)
```xml
<key>PciRoot(0x0)/Pci(0x1D,0x0)</key>
<dict>
    <key>class-code</key>
    <data>AAADAA==</data>  <!-- 0x00030C00 -->
    <key>compatible</key>
    <string>pci8086,1c27</string>
    <key>IOName</key>
    <string>pci8086,1c27</string>
</dict>
```

### 2. UHC5 @ PCI0 (UHC5@1A)
```xml
<key>PciRoot(0x0)/Pci(0x1A,0x0)</key>
<dict>
    <key>class-code</key>
    <data>AAADAA==</data>  <!-- 0x00030C00 -->
    <key>compatible</key>
    <string>pci8086,1c27</string>
    <key>IOName</key>
    <string>pci8086,1c27</string>
</dict>
```

### 3. Critical Fix: ProtocolOverrides
**Discovered:** `UEFI` → `ProtocolOverrides` → `DeviceProperties` was `false` — would have made injections inert.

**Changed to:** `true` (enables DeviceProperties protocol for macOS)

### Rule: All sudo via SSH/subagent must funnel through TermEcho

**Before any sudo command:**
1. Send command to TermEcho socket
2. User sees modal alert on host machine
3. User approves/denies
4. Only on approval → execute sudo
