## 🔬 Detailed Findings

### Finding 1 — Boot Hang Root Cause Identified

- **Before:** Boot hanging at ~1/3 progress bar after crash notice screen
- **Symptom:** 5+ minutes with no progress, system completely frozen
- **Root Cause:** `amfi_get_out_of_my_way=0x7ff` in OpenCore boot-args too aggressive for initial boot
- **Why:** XNU 25 (Tahoe) kernel cannot complete boot sequence with full AMFI bypass active from start
- **Confirmed:** Pattern matches previous sessions where aggressive AMFI caused panics ✅

### Finding 2 — APFS Snapshot State

- **Before:** Mini was set to boot from "clean" snapshot (Session 31 ending state)
- **Finding:** Only ONE snapshot available: `com.apple.os.update-2555E3E58AD284A3D1FD76F8FB071FBE0254898E3EDF47E707B9F6CFB0978E9F` (XID 2239951)
- **Status:** Snapshot marked "(Will revert to this snapshot)" — bless command from Session 31 was successful
- **Issue:** This snapshot appears clean (no OCLP patches applied) but boot still failed
- **Conclusion:** Problem was OpenCore config, not the snapshot content ✅

### Finding 3 — Conservative AMFI Approach Required

- **Before:** `boot-args = keepsyms=1 debug=0x100 -lilubetaall ipc_control_port_options=0 -nokcmismatchpanic amfi_get_out_of_my_way=0x7ff -igfxvesa`
- **After:** `boot-args = keepsyms=1 debug=0x100 -lilubetaall ipc_control_port_options=0 -nokcmismatchpanic -igfxvesa`
- **Change:** Removed `amfi_get_out_of_my_way=0x7ff` entirely
- **How:** Python plistlib direct edit to `/Volumes/EFI/EFI/OC/config.plist`
- **Backup:** Created `config.plist.bak-before-conservative-boot`
- **Confirmed:** Changes written successfully to EFI ✅

### Finding 4 — New Two-Step OCLP Patching Strategy

**Old (Failed) Strategy:**
- Add AMFI bypass to boot-args permanently
- Boot with AMFI disabled
- Run OCLP patches
- Result: Kernel panic during boot before patches can even run

**New (Correct) Strategy:**
1. **Step 1 — Clean Boot:** Boot with NO AMFI bypass → system starts normally
2. **Step 2 — Patch-Time AMFI:** Add AMFI bypass ONLY when running OCLP patch command
3. **Method:** Use `amfi_get_out_of_my_way=1` as boot-arg during patch, OR use OCLP's built-in AMFI handling
4. **Benefit:** System boots reliably, patches can be applied when needed

- **Rationale:** Separate boot stability from patch capability
- **Expected Outcome:** Desktop appears with GPU + USB HID working, Ethernet still absent (expected until patches run)
