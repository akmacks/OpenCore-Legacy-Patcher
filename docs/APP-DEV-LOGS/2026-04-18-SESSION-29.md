## 📋 Executive Summary

Session 28's subagent-induced config rollback (restoring networking) inadvertently hid a critical hardware fact: **EH02 (PCI 0x1A), the secondary EHCI controller, was being put to sleep by macOS Tahoe's aggressive USB power management**, making half of the Mac Mini's rear USB ports effectively invisible.

Adam's physical test—plugging the Seagate 750GB + Belkin hub into the "dead" far-left port—**confirmed EH02 is alive and functional** when a device is inserted. However, this exposed a second issue: **the older Belkin USB 2.0 hub is failing to enumerate on Tahoe**, causing a "hub collapse" where downstream devices (mouse, transceiver, Lexar sticks) are invisible to macOS even though they are physically connected.

This session documents the discovery, the proposed "Unified USB Fix," and a full rollback plan.

## 🔬 Session 28 Close-Out & Session 29 Open

### Session 28 Root Cause (Revised)
Session 28 was triggered by a subagent applying UHCI class-code injections to **PCI function 0** (which is EHCI, not UHCI) on the Sandy Bridge PCH. This broke Thunderbolt Bridge networking. Recovery was done by restoring `config.plist.backup.20260417-210025`.

**Critical lesson learned (Session 28 retrospective):**
> UHCI controllers on the PCH are at PCI functions 1-3. Function 0 is EHCI. Session 27's injection target was wrong. This is why EH02 went to sleep—after the rollback, EH02's ACPI state may have been partially modified by the broken injection in a way that left it in a degraded power state.

## 🆕 New Discovery: The EH02 Sleep Syndrome

### How it was found
Adam plugged the Seagate 750GB (via Belkin hub) into the "dead" far-left USB port (EH02-backed). The disk appeared in `diskutil list` as `disk1` — **proving EH02 hardware is functional**. However, the `ioreg -p IOUSB` tree was empty, indicating **the hub collapsed** and downstream devices were not enumerated.

### Evidence
```
/dev/disk1 (internal, physical):
   #:                       TYPE NAME                    SIZE       IDENTIFIER
   0:      GUID_partition_scheme                        *750.2 GB   disk1    ← SEAGATE VISIBLE
   1:                        EFI EFI                     209.7 MB   disk1s1
   2:                  Apple_HFS Macintosh HD2           749.8 GB   disk1s2
```

### EH02 Power State (Post-Plug-In)
```
EH02@fa000000: "controller-statistics" = {
  "kControllerStatIOCount" = 0,
  "kControllerStatPowerStateTime" = {
    "kPowerStateOff" = "0ms (0%)",
    "kPowerStateSleep" = "0ms (0%)",
    "kPowerStateOn" = "1006ms (0%)",       ← Still near 0 — controller very recently woke
    "kPowerStateSuspended" = "1239746ms (99%)"  ← Was 99% suspended before disk plug-in
  }
}
```

### The "Hub Collapse" Problem
The Belkin hub (model unspecified, likely a older Bus-Powered USB 2.0 hub) is failing macOS Tahoe's USB hub descriptor validation. Tahoe's USB stack (which is based on the modern DriverKit IOUSBHostFamily) is stricter than older macOS versions about:
- Hub descriptor length and format
- Power budgeting descriptors
- `bcdHub` version compliance

When Tahoe rejects a hub, it effectively "collapses" — the hub device disappears from the bus, and all downstream devices are orphaned.

## 🛠️ Proposed Fix: "Unified USB Fix" (3-Part)

### Part 1: EH02 Power-Lock (DeviceProperties Injection)
**Goal:** Prevent EH02 from ever entering the Suspended state. Every time a device is unplugged from an EH02 port, the controller should remain powered on.

**EFI path:** `PciRoot(0x0)/Pci(0x1A,0x0)`

| Property | Value | Rationale |
|---|---|---|
| `kUSBSleepPortCurrentLimit` | `2100` | Standard port current |
| `kUSBWakePortCurrentLimit` | `2100` | Allow wake from any port |
| `AAPL,current-available` | `2100` | Stable power delivery |
| `AAPL,current-extra` | `2100` | Prevent power throttling |
| `UsbConnector` | `0` | Mark as standard Type-A |
| `port-count` | `4` | Expose all 4 ports (2 internal + 2 rear) |
| `kUSBCompanion` | `false` | EH02 does not need companion |

**Implementation:** Add to `DeviceProperties → Add` in `config.plist`.

### Part 2: USB-Map Fix for EH02 (kext merge properties)
**Goal:** Ensure the USB-Map.kext merge properties are correctly applied to EH02 so macOS knows the port layout.

**Target:** `USB-Map.kext/Contents/Info.plist`

Current state of `USB-Map.kext` (from Session 28 audit):
- `IONameMatch` targets `EHC1`/`EHC2` (pre-rename names) — **NEVER MATCHES** the renamed `EH01`/`EH02` in Tahoe
- Merge properties are inert as a result

**Fix:** Update the `USB-Map.kext/Contents/Info.plist` IOKitPersonalities to target `EH01` and `EH02` by their new names.

```xml
<!-- BEFORE (broken): -->
<key>IONameMatch</key>
<array>
    <string>EHC1</string>
    <string>EHC2</string>
</array>

<!-- AFTER (fixed): -->
<key>IONameMatch</key>
<array>
    <string>EH01</string>
    <string>EH02</string>
</array>
```

Also update `kUSBCompanion` and `port-count` for each controller.

### Part 3: UHCI Binding — Carefully (Stage 2 Revisited)
**Goal:** Enable UHCI companion controllers WITHOUT breaking EH02/Thunderbolt Bridge networking.

**Critical insight from Session 27 failure:**
> UHCI controllers on the PCH are at PCI functions 1-3 on the same PCI device as EHCI (function 0). Session 27 injected class-codes at function 0 — destroying EHCI. We must ONLY inject at functions 1-3.

**PCI paths for UHCI injection (not EHCI):**

| Controller | PCI Path | Function | Expected Class-Code |
|---|---|---|---|
| UHC1 | `PciRoot(0x0)/Pci(0x1D,0x1)` | 1 | `0x0C0300xx` → spoof to `0x00030C00` |
| UHC2 | `PciRoot(0x0)/Pci(0x1D,0x2)` | 2 | `0x0C0300xx` → spoof to `0x00030C00` |
| UHC3 | `PciRoot(0x0)/Pci(0x1D,0x3)` | 3 | `0x0C0300xx` → spoof to `0x00030C00` |
| UHC4 | `PciRoot(0x0)/Pci(0x1A,0x1)` | 1 | `0x0C0300xx` → spoof to `0x00030C00` |
| UHC5 | `PciRoot(0x0)/Pci(0x1A,0x2)` | 2 | `0x0C0300xx` → spoof to `0x00030C00` |
| UHC6 | `PciRoot(0x0)/Pci(0x1A,0x3)` | 3 | `0x0C0300xx` → spoof to `0x00030C00` |

**Important:** Do NOT inject at function 0 for any of these PCI devices. Function 0 is EHCI and must retain its native class-code `0x0C0320`.

```bash
# On Mac Mini via SSH, with EFI mounted:
sudo cp -R /Volumes/EFI/EFI/OC/config.plist /Volumes/EFI/EFI/OC/config.plist.backup.20260418-SESSION29
sudo cp -R /Volumes/EFI/EFI/OC/Kexts/USB-Map.kext /Volumes/EFI/EFI/OC/Kexts/USB-Map.kext.backup.20260418-SESSION29
```

### Step 2: If Fix Fails — Boot to TDM
1. Boot Mac Mini holding **Option (⌥)** to show boot picker
2. Select **EFI** volume (OpenCore)
3. Select **Reset NVRAM** if needed
4. If system fails to boot → boot to **macOS Recovery** or **External Drive**
5. Mount EFI: `sudo diskutil mount disk0s1`
6. Restore backup:
   ```bash
   sudo cp /Volumes/EFI/EFI/OC/config.plist.backup.20260418-SESSION29 /Volumes/EFI/EFI/OC/config.plist
   sudo cp -R /Volumes/EFI/EFI/OC/Kexts/USB-Map.kext.backup.20260418-SESSION29/* /Volumes/EFI/EFI/OC/Kexts/USB-Map.kext/
   ```
7. Unmount EFI and reboot normally

### Step 3: If Networking Dies
1. SSH into Mac Mini (if SSH still works)
2. If SSH is dead → boot to TDM
3. Restore `config.plist.backup.20260417-210025` (the pre-Session27 backup)
4. Report session state immediately
