## Root Cause Identified

**VNC "0x0 desktop size" / black screen = no GPU framebuffer driver loaded.**

On Macmini5,3 (Sandy Bridge HD 3000, Device ID `0x0116`), macOS Tahoe has no native GPU driver. Without a framebuffer:
- WindowServer cannot create a renderable surface
- `screencapture` fails with "could not create image from display"
- `loginwindow` cannot complete the GUI session (auto-login panics)
- VNC protocol reports `0x0` desktop dimensions

**Previous state (Sessions 15-17):** WhateverGreen was **disabled** in config.plist because it caused kernel panics when full GPU acceleration was attempted.

**Session 18 fix:** Enable WhateverGreen with **headless framebuffer only** — no hardware acceleration.

## Changes Made (Repeatable Steps)

### 1. EFI config.plist Modifications

**File:** `/Volumes/EFI/EFI/OC/config.plist`

**Change A — Enable WhateverGreen (was disabled)**
```
Kernel/Add[1]: WhateverGreen.kext → Enabled=True
```
WhateverGreen must load immediately after Lilu (position 1 in Kernel/Add array).

**Change B — Add GPU DeviceProperties for headless framebuffer**
```
DeviceProperties/Add/PciRoot(0x0)/Pci(0x2,0x0):
  ig-platform-id:          00000310  (0x10030000 — Sandy Bridge headless)
  framebuffer-patch-enable: 01000000  (true)
  framebuffer-stolenmem:    0000300a  (640 MB)
```

**Why `ig-platform-id 0x10030000`:** This is a headless framebuffer configuration for Sandy Bridge. It tells WhateverGreen to create a virtual framebuffer without enabling full GPU acceleration. The full acceleration stack (hardware rendering, Metal, etc.) is what causes kernel panics on Macmini5,3.

**Why stolenmem 640MB:** Minimum stolen memory for the framebuffer to function. Without sufficient stolen memory, the framebuffer can't allocate VRAM.

**Created `openclawadmin` user** (admin, password: `openclaw2026`) as fallback for VNC login testing. This user did **not** persist through reboot (dscl-created users on sealed system volumes may not survive APFS snapshot rollbacks).

**Fixed `autoLoginUserUID` mismatch:** Was set to 503 (openclawadmin), corrected to 502 (akmacks).

**Cleared `lastLoginPanic`:** The loginwindow panic flag from previous failed login attempts was preventing session completion. Cleared via:
