## 📋 Executive Summary

Mac mini (Macmini5,3, macOS Tahoe 26.4) failed to boot after Session 33's Preboot KC
replacement. Verbose boot log (screenshot) showed kernel panic chain rooted in
`com.apple.iokit.IOSkywalkFamily not found`. Investigation via TDM revealed the true
cause: an Auxiliary Kernel Collection (`AuxiliaryKernelExtensions.kc`) rebuilt on
2026-04-26 contained a baked-in fatal binding error in `RestrictEvents.kext`
(`Failed to bind '_cpuid_info'`). This broke Lilu's early-boot patching, which in turn
prevented OC's injected IOSkywalkFamily from initialising, producing the observed
"not found" errors for all downstream kexts.

Fix: deleted the corrupt Aux KC and purged `/Library/Extensions` of duplicate and
unneeded kexts (RestrictEvents, Lilu, AppleALC, HighPointIOP, HighPointRR,
Pegasus2R2ICON, PromiseSTEX). Only SATSMARTDriver.kext and SATSMARTLib.plugin remain.
macOS will rebuild a fresh Aux KC from this clean state on next boot. Mini ejected from
TDM at session close — boot confirmation is the first task of Session 35.

## 🔬 Detailed Findings

### Finding 1 — Root Cause: Corrupt Aux KC with Fatal RestrictEvents Binding Error
- **Before:** `AuxiliaryKernelExtensions.kc` in Data volume (3.6 MB, April 26 10:38)
  contained RestrictEvents.kext with baked-in error:
  `Failed to bind '_cpuid_info' in 'as.vit9696.RestrictEvents' (at offset 0x24f in
  __TEXT, __text) as could not find a kext which exports this symbol`
- **After:** Aux KC deleted. macOS will rebuild clean on next boot.
- **How:** `sudo rm` via TDM-mounted Data volume from MBP
- **Why fatal:** RestrictEvents is a Lilu plugin. Lilu loads at early boot before IOKit
  subsystem is fully initialised. A binding failure in a Lilu plugin prevents Lilu from
  completing its early patching chain. OC's IOSkywalkFamily injection depends on Lilu's
  patching being applied. With Lilu broken, the injected IOSkywalkFamily cannot
  initialise → all kexts that depend on it report "library not found".
- **Confirmed:** ✅ (fix applied; boot outcome pending)

### Finding 2 — /Library/Extensions Had Duplicate & Alien Kexts
- **Before contents:**
  - AppleALC.kext (duplicate — OC injects from EFI)
  - HighPointIOP.kext (no matching hardware on Macmini5,3)
  - HighPointRR.kext (no matching hardware on Macmini5,3)
  - Lilu.kext (duplicate — OC injects from EFI)
  - Pegasus2R2ICON.kext (no matching hardware)
  - PromiseSTEX.kext (no matching hardware)
  - RestrictEvents.kext (duplicate + broken — OC injects from EFI)
  - SATSMARTDriver.kext (benign — keep)
  - SATSMARTLib.plugin (benign — keep)
- **After:** Only SATSMARTDriver.kext + SATSMARTLib.plugin remain
- **How:** `sudo rm -rf` each removed kext via TDM mount
- **Why duplicates are dangerous:** When both OC-injected and /LE versions of the same
  kext exist, macOS may attempt to load both or choose the wrong version. The /LE
  RestrictEvents was the broken April 26 rebuild. OC has a Kernel->Block entry for
  IOSkywalkFamily to manage versioning — similar conflicts exist for Lilu plugins.
- **Confirmed:** ✅ Verified via `ls /Volumes/Server\ HD\ —\ Data\ 1/Library/Extensions/`

### Finding 3 — OC IOSkywalkFamily Injection Chain (How It Should Work)
- OC EFI injects `IOSkywalkFamily.kext` (840 KB, Sept 29 2025, version 1.0) from
  `EFI/OC/Kexts/`
- `config.plist` has a `Kernel->Block` entry `Allow IOSkywalk Downgrade` that blocks
  the system's IOSkywalkFamily (MinKernel 23.0.0), ensuring only OC's version loads
- The system's `BootKernelExtensions.kc` (confirmed Mar 20) embeds IOSkywalkFamily
  but the block entry prevents it from loading
- For OC injection to work, Lilu must complete early patching successfully
- The broken RestrictEvents in Aux KC prevented Lilu from completing → IOSkywalkFamily
  injection failed → all dependents (AppleIPAppender, IOSkywalkFamily subclasses) failed
- **Confirmed:** `strings BootKernelExtensions.kc | grep IOSkywalkFamily` → present ✅

### Finding 4 — Session 33 Preboot KC Fix Was Correct But Not Sufficient
- Session 33 correctly identified and fixed a corrupted `BootKernelExtensions.kc` in
  the Preboot volume (confirmed by softwareupdated crash reports from April 25/26)
- However, the Aux KC corruption in the Data volume was a separate, co-existing problem
- Both corruptions were caused by the same April 25 23:09 shutdown stall that interrupted
  both the OS updater and a prior OCLP patching session
- Session 33's fix resolved the Preboot KC → boot progressed further than before
- Session 34's fix resolves the Aux KC → Lilu + IOSkywalkFamily chain should now work
- **Status:** Both known corruptions now fixed

### Finding 5 — OC config.plist Boot-Args (Current State)

  -nokcmismatchpanic -igfxvesa -v`

- 22 kexts injected by OC including IOSkywalkFamily, Lilu, RestrictEvents, AppleALC,

- All kexts required for USB, Ethernet, Audio are present in EFI
- `-v` flag is active (added Session 33) — good for diagnosing any remaining issues
- **Note:** `-igfxvesa` forces VESA framebuffer — GPU acceleration disabled (correct for
  Session 34, prevents Sandy Bridge GPU panic)
