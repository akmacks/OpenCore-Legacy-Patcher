## Action Taken — Stage 1: EHCI ACPI Renames

### Why This Was Applied (independent analysis, confirmed against repo docs)

Based on prior session analysis (Sessions 17–20), the EHCI controllers (`EHC1`, `EHC2`) were going comatose after Tahoe boot — `kUSBCompanion: false`, `port-count: 1`, `usb-port-type: 255`, zero I/O operations. The `USB-Map-Tahoe.kext` format fix from Session 19 restored VBUS power, but the controllers remained non-functional beyond powering a hub.

The root cause: `AppleUSBEHCIPCI` matches by ACPI device name (`EHC1`/`EHC2`). When matched, it applies Apple's **built-in port map** from `AppleUSBHostPlatformProperties.kext`, which is for a different Mac model and is completely wrong for Macmini5,3. With no usable port map, the controller creates one phantom port and does nothing.

The fix: rename `EHC1` → `EH01` and `EHC2` → `EH02` via ACPI table patches in `config.plist`. This causes `AppleUSBEHCIPCI`'s name match to **fail**, forcing it to fall back to the ACPI-provided `_UPC`/`_PLD` port descriptors — which are provided by the SSDT we're planning to inject next.

### Changes Applied

**File:** `/Volumes/EFI/EFI/OC/config.plist` (EFI partition)

Two ACPI patches added to the `ACPI → Patch` array:

| # | Comment | Find | Replace | Table |
|---|---|---|---|---|
| 2 | `EHC1 rename to EH01 - avoid Apple port map conflict` | `EHC1` (45 48 43 31) | `EH01` (45 48 30 31) | DSDT |
| 3 | `EHC2 rename to EH02 - avoid Apple port map conflict` | `EHC2` (45 48 43 32) | `EH02` (45 48 30 32) | DSDT |

It is **consistent with OCLP's ACPI patching philosophy** but is **not documented in the existing repo** — meaning it is either untested or a novel approach for this specific machine.
