## 1. Incident: Subagent Class-Code Injection Broke Networking

**Time:** Change applied ~21:00 AEST Apr 17 (by subagent session `mini-usb-fix-ssh`)

### What Happened

A subagent spawned in Session 27 applied two changes to the Mac Mini's OpenCore `config.plist` that broke all networking:

1. **Class-code injection at wrong PCI function**: Added `class-code = 0x00030C00` (UHCI class code) to `PciRoot(0x0)/Pci(0x1D,0x0)` and `PciRoot(0x0)/Pci(0x1A,0x0)`. On Sandy Bridge PCH, function 0 at these devices is the **EHCI controller**, not UHCI. The injection corrupted EHCI device matching instead of enabling UHCI.

2. **Enabled ProtocolOverrides → DeviceProperties**: Changed from `false` to `true`. This was needed to activate the class-code injections, but it also activated the existing audio (`apple-layout-id`) and WiFi (`brcmfx-country`) DeviceProperties that were previously inert (because `DeviceProperties = false` made them passive).

### Result
- **All networking died**: No Ethernet, no Wi-Fi, no Bluetooth, no Thunderbolt Bridge
- Mini became unreachable — put into Target Disk Mode (TDM) for recovery

### Why It Broke
- On Sandy Bridge PCH, UHCI controllers share PCI devices with EHCI. Function 0 = EHCI controller. The subagent targeted function 0 thinking it was UHCI.
- `ProtocolOverrides → DeviceProperties` was `false` for a reason — changing it has system-wide effects beyond just the intended injection. The audio and WiFi properties that were previously passive became active, potentially changing driver behavior.

### Key Facts From Project Docs

1. **USB-Map.kext v1.0 is intentionally inert** — IONameMatch targets EHC1/EHC2 (pre-rename names), so merge properties never apply. This is **correct**. Session 23 proved that making it match (v1.1 with EH01/EH02) breaks USB completely on Tahoe.

2. **kUSBCompanion=false is correct** — On Tahoe, EHCI handles USB 1.x via Transaction Translator. UHCI companion model is legacy and not needed for current functionality.

3. **Session 27's class-code approach was wrong** — Targeting function 0 hit EHCI instead of UHCI, and enabling DeviceProperties had side effects beyond the intended fix.

4. **The bluetoothd crashes** (every ~16 min) are visible in the Mini's crash logs from today. This is expected — Bluetooth is internally USB-attached and affected by the broken USB state.

5. **ACPI renames (EHC1→EH01, EHC2→EH02) are working** — Session 22 confirmed 6 EHCI ports and 3 USB devices after reboot.

6. **The Mini's crash logs** show `bluetoothd` crashing every ~16 minutes from uptime 980s onwards today. This predates the subagent change — the Mini was booted with the broken config since early morning.

## 7. Lessons Learned

1. **Always read project docs before making changes** — Session 27's subagent didn't check that function 0 on Sandy Bridge PCH is EHCI, not UHCI
2. **ProtocolOverrides flags have system-wide effects** — changing DeviceProperties from false to true activates ALL DeviceProperties, not just the new ones
3. **Always back up config.plist before modifying** — the backup saved us
4. **Always verify PCI function assignments** before injecting DeviceProperties
5. **USB-Map.kext must remain inert on Tahoe** — making it match EH01/EH02 breaks USB (Session 23)
6. **The ACPI fallback path is the correct mechanism** for EHCI port configuration on Tahoe — NOT merge kext port dictionaries
